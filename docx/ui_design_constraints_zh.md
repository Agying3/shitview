# shitview UI 与布局硬性约束

更新时间：2026-08-11

本文档是 Rust + Slint 正式实现的 UI、布局和交互验收基线。后续开发不能为了性能、实现便利或视觉效果绕开这些约束；若工程目标之间发生冲突，必须先明确取舍并更新本文档。

## 1. 空间利用

- 画布必须充分利用可用空间。
- 节点之间要有稳定留白，不能拥挤。
- 分区内部不能出现与内容数量不匹配的大面积空洞。
- 禁止用固定行数、固定容量矩阵制造大量空槽。
- 布局应根据真实子文件数量、节点尺寸和分区边界动态计算。

## 2. 初始全局视图

- 项目打开后的原始状态必须展示全局结构。
- 所有进入当前可见集合的文件方块都必须出现在全局视图中。
- 文件名不能因为性能 LOD 直接变成空白方块。
- 文字必须保持清晰，不能依靠极小字号勉强塞入。

### 超大项目视口规则

- 主视口优先保证文件方块和名称清晰，禁止为了塞入 10,000 个节点而无限缩小文字。
- 节点规模过大时允许一部分节点位于当前屏幕外，通过画布平移访问。
- 小地图必须始终展示完整项目分布，并标出当前主视口覆盖区域。
- 小地图支持点击和拖动定位，作为超大项目的全局导航入口。
- “原始状态可看到全局”在超大项目中由小地图承担；主视口不强制同时容纳全部节点。

## 3. 碰撞与分区边界

- 任意两个文件或目录方块不能重叠。
- 自动布局必须在落位前解决碰撞。
- 用户拖动节点时必须进行实时碰撞检测，不能允许节点穿入其他节点。
- 外侧分区框必须始终包含其所属文件方块。
- 所属文件被拖动后，分区边界必须实时或同帧重算，不能留在旧位置。
- 分区之间不能重叠；分区不能嵌套成无意义的多层大框。

## 4. 拖动体验

- 文件方块必须从按下开始实时跟随鼠标，体验接近手机桌面拖动应用图标。
- 禁止只移动预览框、选中框或幽灵占位，而让原方块停在旧位置。
- 拖动期间方块、文字、连接线、所属分区边界和碰撞反馈必须保持一致。
- 拖动事件不能产生队列积压、明显延迟或松手后跳变。
- 画布空白区域拖动用于平移视角，行为接近手机地图。

## 5. 文字避让

- 分区标题不能与文件方块或文件文字重叠。
- 文件文字必须限制在文件方块内部。
- 长文件名应使用明确的截断规则，并在检查器中提供完整名称和路径。
- 布局计算必须把标题牌区域视为障碍物。

## 6. 文字与电路板视觉

- 文件名和分区名必须清晰、稳定、具有足够对比度。
- 主视觉采用暗色电路板风格：深色板材、绿色正交走线、克制的彩色元件边线和低透明玻璃分区。
- 颜色用于表达目录、文件、状态或分区差异，不能把整个画面染成单一绿色或高饱和彩色矩阵。
- 节点采用微圆角，不使用夸张胶囊形状。
- 连接线、节点、标题和分区边界不能发生无意义的视觉穿插。

## 当前实现不符合项

- 小项目布局仍按树叶纵向排布，空间利用率不足。
- 当前全局缩放无法同时保证全部文件名清晰。
- 拖动使用覆盖层，原始光栅节点仍留在旧位置，不满足“原方块实时移动”。
- 拖动过程中没有实时节点碰撞解算。
- 分区边界不会在每个拖动帧重算。
- 分区标题尚未作为布局障碍物参与碰撞。

## 后续实现原则

- 不再继续堆叠 Slint 覆盖层补丁。
- 将场景拆分为可更新的节点、文字、连接线和分区边界数据。
- 拖动时只更新受影响节点、边和分区，不重建整张场景。
- 使用空间索引完成邻域碰撞和分区边界更新。
- 每次 GUI 修改都必须进行真实 release 窗口截图和拖动测试。
